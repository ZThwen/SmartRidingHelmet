# 语音交互可行性分析

> 日期: 2026-05-26  
> 对应: Step C 需求 R13 — 语音指令

---

## 1. 背景

骑行中无法低头操作手机。理想方案是直接用语音控制："开始导航""结束骑行""打开头灯"。  
问题是：谁来听、谁来说、怎么做？

---

## 2. 硬件能力

| 组件 | 音频相关能力 |
|:-----|:------------|
| EC200U | Audio 输出 J402（8Ω/800mW speaker），音频输入通道（文档有，硬件未确认接麦克风） |
| STM32F413ZH | 1.5MB SRAM，170MHz Cortex-M4，无 DSP，浮点运算能力有限 |
| 头盔环境 | 骑行风速 20-40km/h，风噪 80-100dB，无专用降噪结构 |

---

## 3. 两条路分开分析

### 3.1 TTS（语音播报）— 可以做 ✅

**原理**：控制器下发音频数据 → EC200U Audio 输出 → speaker 播放。

**可行性**：EC200U 支持 Audio 输出，已有 J402 接口。导航指令（"前方 50 米左转"）可以提前在手机端合成音频，或预录为短音频文件，通过 TSL 触发播放。

**方案**：

```
小程序输入目的地
  → 云端规划路线
  → 逐条导航指令下发 TSL(ID10/11/12)
  → EC200U 收到 → Audio 播放预录音频
```

**复杂度**：低。Audio 输出已在设备端调通（移远文档有 AT 指令）。只需约定 TSL ID 映射。

**定位**：Step B。

### 3.2 ASR（语音识别听用户指令）— 需要借手机做

#### 方案 A：头盔本地识别 ❌ 行不通

| 关卡 | 为什么不行 |
|:-----|:----------|
| 算力 | STM32F413 只有 1.5MB SRAM，跑不了任何 ASR 模型。最小的语音识别模型（如 TensorFlow Lite Micro 的 keyword spotting）也需要至少 256KB SRAM + Flash 存储模型权重，且模型精度极差 |
| 风噪 | 头盔没有专用降噪麦克风阵列。80dB 风噪下，SNR 为负，任何 ASR 引擎都无法工作 |
| 功耗 | STM32 持续处理音频流会让电池时间缩短 50%+ |

**结论**：❌ 不推荐。

#### 方案 B：EC200U 上传云端识别 ❌ 不可靠

| 关卡 | 为什么不行 |
|:-----|:----------|
| 噪声 | 上传前没有降噪处理，云端 ASR 对强噪声输入准确率低于 30% |
| 延迟 | 4G 上传音频 → 云端处理 → 返回，往返 1-3 秒。骑行中拐弯错过路口时指令才到 |
| 断网 | 隧道/山区 4G 中断，命令丢失 |
| 功耗 | 持续上传音频流，4G 模块电流 200-400mA，远高于轮询的 50mA |

**结论**：❌ 不推荐。

#### 方案 C：手机微信 ASR → 下发头盔 ✅ 可行

| 优势 | 说明 |
|:-----|:-----|
| 硬件已就绪 | 手机在用户兜里，自带降噪麦克风阵列 |
| ASR 引擎成熟 | 微信小程序语音识别 API，识别率高 |
| 风噪可控 | 低头对着手机说话，风噪影响小 |
| 网络瓶颈解除 | ASR 在小程序端完成或通过微信服务端，不依赖 4G 上传音频流 |
| 无新增硬件成本 | 零成本，纯软件改动 |

**流程图**：

```
用户语音："开始导航"
  ↓
手机麦克风（自带降噪）
  ↓
微信小程序语音识别 API（云端/WiFi）
  ↓
小程序解析为指令
  ↓
移远云 sendTsl → EC200U
  ↓
EC200U Audio 输出 TTS 播报
"导航已开始，前方 50 米左转"
```

**复杂度**：中。主要工作是微信小程序的语音识别集成 + 指令 NLP 解析。

**定位**：Step C（小程序先完成 Step B 导航功能后，再叠加语音输入）。

---

## 4. 汇总

| 技术路线 | 可行性 | 复杂度 | 新增硬件 | 推荐 |
|:---------|:------|:-------|:---------|:----|
| 头盔本地 ASR | ❌ 算力不足 | 极高 | 降噪麦克风 | 不推荐 |
| 4G 上传云端 ASR | ❌ 噪声+延迟 | 高 | 降噪麦克风 | 不推荐 |
| 手机本地 ASR | ✅ 成熟 | 低 | 无 | ~~Step C 推荐~~ |
| 手机微信语音 API | ✅ 最成熟 | 中 | 无 | **Step C 推荐** |
| EC200U TTS 播报 | ✅ 可行 | 低 | 无 | **Step B 推荐** |

## 5. 执行路径

```
Step B ✅ → 导航 TTS 播报（手机规划 → 下发给头盔播报）
               └── 只需 TSL ID 映射，不涉及语音识别

Step C 📅 → 手机语音命令（微信语音 API → 小程序解析 → 下发给头盔）
               └── 依赖 Step B 的 TTS 播报链路已就绪
               └── EC200U 只管播反馈，不管听
```

---

## 6. 关键结论

EC200U **可以说话（TTS）但不用它来听（ASR）**。  
听的工作交给手机——它本身就在用户手里，且自带降噪麦克风和成熟的语音识别 API。  

EC200U 的角色是 **Voice Response（语音响应）**，不是 Voice Input（语音输入）。
