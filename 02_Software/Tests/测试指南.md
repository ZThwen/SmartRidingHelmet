# 智能骑行头盔 - 测试规范指南

> **文档目的**：定义标准化测试流程，确保每个模块独立可用，集成时无误
>
> **核心原则**：单模块测试 → 集成环境测试 → 系统集成测试

---

## 1. 测试分类与目的

| 测试类型 | 测试范围 | 核心目的 | 文件命名 |
|---------|---------|---------|---------|
| **单模块测试** | 仅模块实例 | 验证API可用性、数据正确性 | `test_<模块名>.py` |
| **集成环境测试** | EventBus + 主循环 | 验证事件流转、模块协作能力 | `test_<模块名>_integration.py` |
| **系统集成测试** | 所有模块 | 验证完整业务流程 | `test_system_full.py` |

**关键说明**：
- **单模块测试**：验证模块本身功能正常，不依赖其他模块
- **集成环境测试**：模拟真实运行环境，验证模块能与EventBus正确协作
- **系统集成测试**：所有模块一起运行，验证完整业务流程

---

## 2. 标准化测试流程

### 2.1 单模块测试流程

**必须包含的测试内容**：

| 序号 | 测试项 | 测试目的 | 必要性 |
|------|--------|---------|--------|
| 1 | **初始化测试** | 验证 `init()` 成功 | 必须 |
| 2 | **状态查询测试** | 验证 `get_status()` 返回正确 | 必须 |
| 3 | **数据采集测试** | 验证数据在合理范围 | 驱动层必须 |
| 4 | **连续运行测试** | 验证多次调用稳定 | 必须 |
| 5 | **异常处理测试** | 验证错误能正确捕获和处理 | 必须 |
| 6 | **边界条件测试** | 验证极端情况下的行为 | 推荐 |

**测试步骤模板**：

```
步骤1: 创建模块实例
步骤2: 调用 init()，验证初始化成功
步骤3: 调用 get_status()，检查 is_init=True
步骤4: 多次调用 tick()，验证数据采集正常
步骤5: 调用 get_data()，验证数据有效性
步骤6: 连续运行N次，验证稳定性（无崩溃、无内存泄漏）
步骤7: 模拟异常情况，验证错误处理正确
```

**验收标准**：
- ✓ 所有必须项测试通过
- ✓ 数据在合理范围内
- ✓ 无内存泄漏
- ✓ 异常情况能正确处理

---

### 2.2 集成环境测试流程

**必须包含的测试内容**：

| 序号 | 测试项 | 测试目的 | 必要性 |
|------|--------|---------|--------|
| 1 | **环境搭建** | 创建EventBus、订阅事件 | 必须 |
| 2 | **模块初始化** | 在集成环境中初始化模块 | 必须 |
| 3 | **事件发布测试** | 验证事件正确发布到EventBus | 必须 |
| 4 | **事件接收测试** | 验证订阅者能接收到事件 | 必须 |
| 5 | **主循环运行测试** | 模拟真实主循环环境运行 | 必须 |
| 6 | **动态配置测试** | 验证配置事件能动态修改参数 | 推荐 |
| 7 | **长时间运行测试** | 验证持续运行稳定 | 推荐 |

**测试步骤模板**：

```
步骤1: 创建 EventBus 实例
步骤2: 订阅该模块会发布的事件
步骤3: 创建模块实例，传入 EventBus
步骤4: 调用 init()，验证在集成环境中初始化成功
步骤5: 运行主循环（while + tick + pump）
步骤6: 验证事件发布：检查是否收到事件回调
步骤7: 验证事件数据：检查事件携带的数据是否正确
步骤8: （可选）发布配置更新事件，验证动态配置生效
步骤9: 持续运行足够时间，验证稳定性
```

**验收标准**：
- ✓ 事件能正确发布到EventBus
- ✓ 订阅者能正确接收事件
- ✓ 事件数据完整且正确
- ✓ 在主循环环境中运行稳定
- ✓ 与EventBus协作无异常

**集成环境测试的意义**：
- 验证模块能在最终系统中正常工作
- 发现单模块测试无法发现的问题（事件协作、时序问题）
- 确保模块集成时不会引入bug

### 2.3 系统集成测试流程

**测试内容**：

| 序号 | 测试项 | 测试目的 |
|------|--------|---------|
| 1 | 系统启动测试 | 所有模块按顺序初始化成功 |
| 2 | 模块协作测试 | 模块间事件流转正确 |
| 3 | 业务流程测试 | 完整业务场景能正确执行 |
| 4 | 长时间稳定性测试 | 系统持续运行无崩溃 |
| 5 | 异常恢复测试 | 异常情况系统能恢复或降级 |

**验收标准**：
- ✓ 所有模块初始化成功
- ✓ 事件流转正常
- ✓ 业务流程完整
- ✓ 系统稳定运行

## 3. 各类模块测试要点

### 3.1 传感器驱动模块

**单模块测试要点**：
- I2C/UART/ADC 通信正常
- 数据采集准确
- 数据范围合理（温度、湿度、加速度等）
- 数据有效性标志正确

**集成环境测试要点**：
- 发布 `SENSOR_DATA_READY` 事件
- 事件携带完整数据（值 + 时间戳 + 有效性）
- 采样周期符合配置
- 数据无效时发布 `SENSOR_ERROR` 事件

---

### 3.2 执行器驱动模块

**单模块测试要点**：
- GPIO/PWM 控制正常
- 状态切换正确（开/关/闪烁等）
- 响应及时

**集成环境测试要点**：
- 能响应控制事件
- 状态变化发布反馈事件
- 多次控制无异常

---

### 3.3 业务服务模块

**单模块测试要点**：
- 算法逻辑正确
- 数据处理准确
- 异常情况能正确处理

**集成环境测试要点**：
- 订阅依赖的事件
- 处理后发布正确的事件
- 与其他服务协作正常

---

### 3.4 网络通信模块

**单模块测试要点**：
- 连接/断开正常
- 数据收发正确
- 断线重连机制有效

**集成环境测试要点**：
- 网络操作不阻塞主线程
- 连接状态发布事件通知
- 数据上传成功/失败发布对应事件

---

## 7. 常见测试失败原因

| 失败现象 | 可能原因 | 解决方法 |
|---------|---------|---------|
| 初始化失败 | 硬件未连接、地址错误 | 检查硬件连接和配置 |
| 数据异常 | 传感器故障、通信错误 | 检查传感器状态和通信 |
| 事件未接收 | 未订阅、事件名错误 | 检查订阅代码和事件名常量 |
| 阻塞卡死 | tick()中有阻塞操作 | 移除阻塞操作或独立线程 |
| 内存泄漏 | 未释放资源、循环引用 | 检查资源释放和对象生命周期 |

### 变更背景

Phase 3 将 ControlService 从直接调用模块重构为纯事件驱动架构：
- **v1 架构**：ControlService 注入 LightService/AudioDriver/AlarmService，直接调用方法

- **v3 架构（当前）**：v2 + BLEService 环形缓冲区 + TTS 反馈（CMD_TTS_MAP + _maybe_tts）
