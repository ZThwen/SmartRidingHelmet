## 关键调试日志
```
=== VoiceDriver 单元测试 ===
uart=2, baud=115200
0x00 → wake
0x01 → light_on
0x09 → alarm_sos
0x0E → query_status
0x0F → query_speed
0x10 → query_temp
全部 20 条映射: 0x00~0x13
unknown: 0xFF → 无崩溃

=== Voice + ControlService 联合 ===
0x01 → light_on → LIGHT_CONTROL
0x06 → volume_up → VOLUME_CONTROL
0x09 → alarm_sos → ALARM_CONTROL
0x0B → power_save → POWER_STATE_CHANGE
0x10 → query_temp → TTS_REQUEST
events: VOICE → LIGHT/VOL/ALARM/POWER/TTS → STATE

=== Voice E2E ===
0x01 → PWM duty=50, mode=manual
0x06 → 音量 5→5 (上限), TTS "音量增加"
0x10 → TTS "温度信息暂不可用"
stealth 报警 → TTS 抑制 → 取消后恢复 "音量降低"
- 发现：ControlService 当前通过 `EVENT_TTS_REQUEST` 发起 TTS，而 DisplayService/NavigationService/AlarmService 已直接注入 AudioDriver 并调用播放接口，业务层调用方式不统一。
- 方案 A：ControlService 可选注入 `audio_driver`，优先直接调用 `audio_driver.play_tts(text)`，若未注入则回退到 `EVENT_TTS_REQUEST`；兼容现有事件路径，逐步统一调用风格。
```
