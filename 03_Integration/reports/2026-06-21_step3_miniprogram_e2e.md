# Step 3 联动小程序 E2E 测试清单

> 日期：2026-06-21
> 测试环境：真实硬件 + 微信小程序
> 前置条件：main.py 已集成 16 模块（含 NavigationService）

---

## 测试环境准备

### 硬件
- [ ] NUCLEO-F413ZH 板子供电正常
- [ ] EC200U 4G 模块天线连接
- [ ] 喇叭已连接（J402 接口）
- [ ] LCD 屏幕正常显示

### 软件
- [ ] main.py 已上传到板子
- [ ] 微信小程序已加载到微信开发者工具
- [ ] 手机蓝牙已开启

### 启动顺序
1. 板子上电，运行 main.py
2. 确认串口输出 `✅ 系统就绪，16 个模块在线`
3. 手机打开微信小程序
4. 小程序扫描 BLE 设备

## 测试场景

### 场景 1：BLE 扫描与连接

| 步骤 | 操作 | 预期结果 | 实际结果 |
|------|------|---------|---------|
| 1.1 | 小程序点击"扫描设备" | 显示设备列表 | |
| 1.2 | 选择 `SmartHelmet-66ccff` | BLE 连接成功 | |
| 1.3 | 观察小程序状态 | 显示"已连接" | |
| 1.4 | 观察板子串口 | `[ble] 手机已连接` | |

**验证点**：
- [ ] FFF1 Notify 已启用（小程序能收到头盔数据）
- [ ] FFF2/FFF3/FFF4 Write 可用（小程序能发送指令）

### 场景 2：传感器数据推送 (FFF1 → 小程序)

| 步骤 | 操作 | 预期结果 | 实际结果 |
|------|------|---------|---------|
| 2.1 | 观察小程序首页 | 显示实时温湿度 | |
| 2.2 | 等待 5 秒 | 数据刷新 | |
| 2.3 | 观察速度显示 | 显示 GNSS 速度（或 0） | |
| 2.4 | 观察位置显示 | 显示经纬度（或 0,0） | |

**验证点**：
- [ ] 小程序收到 `{"t":0,"d":{...}}` 格式数据
- [ ] 温湿度数据与实际一致
- [ ] 数据每 2 秒刷新一次

---

### 场景 3：导航指令下发 (小程序 → FFF2 → 头盔)

| 步骤 | 操作 | 预期结果 | 实际结果 |
|------|------|---------|---------|
| 3.1 | 小程序设置目的地 | 开始导航 | |
| 3.2 | 等待 5 秒 | 小程序发送 FFF2 导航指令 | |
| 3.3 | 观察板子串口 | `[nav] 收到事件: ...` | |
| 3.4 | 观察喇叭 | TTS 播报"前方 XXX 米..." | |
| 3.5 | 观察 LCD | 显示导航信息 | |

**验证点**：
- [ ] 小程序每 5 秒发送一次导航指令
- [ ] 指令格式：`{"a":"nav","d":{"dir":"...","dist":...,"road":"..."}}`
- [ ] 板子收到指令后 TTS 播报
- [ ] LCD 显示导航行（方向符号 + 距离 + 路名）

**导航指令示例**：
```json
{"a":"nav","d":{"dir":"right","dist":200,"road":"中山路"}}
→ TTS: "前方200米右转进入中山路"
→ LCD: "> 200m 中山路"
```

| 步骤 | 操作 | 预期结果 | 实际结果 |

| 4.4 | 观察板子串口 | `[alarm] 报警激活` | |
