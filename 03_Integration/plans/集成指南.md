## 第一部分：集成前的防御性代码审查（鲁棒性排雷）
*嵌入式系统的魔鬼藏在"纸面设计"与"物理硬件"的交界处。在合入 `main.py` 前，必须逐一排查以下隐性风险。*

### 1.1 MicroPython 线程与内存安全
*   **网络/TTS 线程栈溢出（Hard Fault）**：`CloudService`、`LarkCloudService` 和 `NavigationService` 的 TTS 播报使用了 `_thread`。在弱网重连或长语音播报时，默认栈空间极易溢出导致死机。
    *   **对策**：所有 `_thread.start_new_thread` 必须显式指定栈大小（如 `_thread.stack_size(8192)`），且线程入口函数最外层必须包裹 `try...except` 防止线程静默死亡。
*   **BLE Modem 线程的"脏数据击穿"**：`BLEService` 的回调在 EC200U 的 modem 线程（中断上下文）执行。
    *   **对策**：回调函数必须被 `try-except` 死死包裹；写入 `cmd_buffer`（环形缓冲区）的数据必须做长度截断，宁可丢弃脏数据，绝不能让异常抛出导致 BLE 协议栈瘫痪。

### 1.2 硬件资源的互斥与抢占
*   **音频通道的"抢占死锁"**：EC200U 的 `quectel.Audio` API 是单例独占的。导航 TTS 和 碰撞报警音 同时调用会导致底层挂死。
    *   **对策**：`AudioDriver` 内部必须实现**软件优先级队列**。收到高优先级 `play_file(alarm)` 时，必须主动 `stop()` 打断 TTS 线程，释放句柄后再播放报警音。
*   **GNSS 与 LBS 的"切换黑洞"**：EC200U 限制不能同时运行 GNSS 和 LBS。
    *   **对策**：`main.py` 中必须通过配置二选一初始化；或实现带**超时恢复机制**的动态切换（GNSS 丢失触发 `EVENT_GPS_LOST` 后，`deinit` GNSS 再 `init` LBS，若超时失败则彻底重启定位模块）。
*   **I2C1 总线竞争**：`Temp_Humid` 和 `IMU` 共享 I2C1。
    *   **对策**：确保所有 I2C 操作都在主线程的 `tick()` 中串行执行，**严禁**后台网络线程直接读写 I2C。

### 1.3 外部输入的"污染"与防误触
*   **BLE 断连重连的"队列雪崩"**：
    *   **对策**：`BLEService` 收到 `EVENT_BLE_DISCONNECTED` 时，**强制清空** `send_queue` 和 `_ctrl_snapshot`；重连时只发一次全量状态快照（`t=7`），绝不重播历史队列。

### 1.4 状态机的死锁与伦理冲突
*   **LCD 状态锁的"永久死锁"**：`LCDDriver` 的 `display_mode` 锁在报警时上锁，若 `EVENT_ALARM_CANCELED` 丢失，LCD 将永久卡在报警画面。
    *   **对策**：增加**超时自动解锁机制**（如 60 秒无报警事件自动恢复 normal）。
*   **静默报警 (STEALTH) 与 真实碰撞 (COLLISION) 冲突**：
    *   **对策**：定义最高优先级覆盖规则：`硬件碰撞 (Level 3) > 静默报警模式`。严重车祸必须强制打破静默，触发最大音量声光报警。

### 1.5 系统级兜底机制
*   **主循环假死**：
    *   **对策**：开启硬件 WDT（看门狗，如 8 秒）。核心模块（Collision, BLE）定期更新"心跳时间戳"，主循环喂狗前检查时间戳，若核心模块卡死超过 5 秒，主动触发 Soft Reset。

## 第二部分：`main.py` 编排与初始化策略（搭骨架）

### 2.1 严格的四阶段初始化顺序
必须遵循"传感器(D1) -> 执行器+接口(D2) -> 网络(D3) -> 业务服务(S4)"的单向依赖顺序。Phase 4 新模块插入位置如下：

```
阶段 1（传感器）：Temp_Humid, IMU, GNSS, Light
阶段 2（执行器+接口）：Button, LED, Audio, LCD, PWM_LED, VoiceDriver
阶段 3（网络）：BLEDriver
阶段 4（业务服务）：Collision, Alarm, Cloud, Display, LightService, BLEService, ControlService, NavigationService
```

### 2.2 依赖注入（DI）闭环与判空保护
*   **规则**：Service 层严禁自己 `import` 底层硬件，必须通过构造函数注入（如 `DisplayService(lcd=lcd_drv, audio=audio_drv)`）。
*   **防御**：`ControlService` 和 `NavigationService` 在调用注入的 `audio`、`light`、`ble` 对象前，**必须加 `if self.audio:` 的判空保护**，防止依赖模块初始化失败导致 `NoneType` 崩溃。

### 2.3 Fail-Safe 容错降级机制
*   **规则**：`main.py` 的初始化循环必须用 `try...except` 包裹每个模块的 `init()`。
*   **灵魂拷问**：如果 `VoiceDriver` (UART线没接好) 初始化失败，系统会不会直接抛出异常导致重启？必须确保它只打印 Error Log，然后**跳过并继续**初始化后续模块。

### 2.4 main.py 代码模板

```python
"""
brief 智能骑行头盔系统入口 — v2 正式版
note 集成 19 个模块（5 传感器 + 5 执行器 + 1 网络 + 8 Service，不含MQTT云连接）
"""
import sys
import time

sys.path.append("..")

from core.Event_Bus import EventBus
from core.config import EVENT_SYSTEM_READY

# 传感器
from Drivers.sensor.Temp_Humid import TempHumidDriver
from Drivers.sensor.imu import IMUDriver
from Drivers.sensor.Gnss import GNSSDriver
from Drivers.sensor.Light import LightSensorDriver

# 执行器+接口
from Drivers.interface.Button import Button
from Drivers.actuator.LED import LEDDriver
from Drivers.actuator.Audio import AudioDriver
from Drivers.actuator.LCD import LCDDriver
from Drivers.actuator.PWM_LED import PWMLEDDriver
from Drivers.interface.Voice import VoiceDriver

# 网络
from Drivers.network.BLE import BLEDriver

# 服务
from Modules.collision_service import CollisionService
from Modules.alarm_service import AlarmService
# from Modules.cloud_service import CloudService  # MQTT云连接暂不集成
from Modules.display_service import DisplayService
from Modules.light_service import LightService
from Modules.ble_service import BLEService
from Modules.control_service import ControlService
from Modules.navigation_service import NavigationService


def main():
    """
    brief 系统入口: 20 个模块全集成，v2 正式版
    """
    print("智能骑行头盔系统启动...")

    # 1. 创建事件总线
    event_bus = EventBus()
    event_bus.debug = True

    # 2. 创建模块实例
    # --- 阶段1: 传感器 ---
    temp_humid = TempHumidDriver(event_bus)
    imu = IMUDriver(event_bus)
    gnss = GNSSDriver(event_bus)
    light = LightSensorDriver(event_bus)

    # --- 阶段2: 执行器+接口 ---
    button = Button(event_bus)
    led = LEDDriver(event_bus)
    audio = AudioDriver(event_bus)
    lcd = LCDDriver(event_bus)
    pwm_led = PWMLEDDriver(event_bus)
    voice = VoiceDriver(event_bus)

    # --- 阶段3: 网络 ---
    ble = BLEDriver(event_bus)

    # --- 阶段4: 服务（注入 Device 引用）---
    collision = CollisionService(event_bus)
    alarm = AlarmService(event_bus, led=led, audio=audio)
    # cloud = CloudService(event_bus)  # MQTT云连接暂不集成
    display = DisplayService(event_bus, lcd_driver=lcd, audio_driver=audio)
    light_svc = LightService(event_bus, pwm_led=pwm_led)
    ble_svc = BLEService(event_bus, ble_driver=ble)
    ctrl_svc = ControlService(event_bus, temp_humid=temp_humid, gnss=gnss)
    nav_svc = NavigationService(event_bus, audio_driver=audio, lcd_driver=lcd)

    # 3. 按序初始化
    init_order = [
        temp_humid, imu, gnss, light,           # 传感器
        button, led, audio, lcd, pwm_led, voice, # 执行器+接口
        ble,                                      # 网络
        collision, alarm, display,               # 服务v1（不含MQTT）
        light_svc, ble_svc, ctrl_svc, nav_svc    # 服务v2
    ]
    failed = []

    print("\n[初始化阶段]")
    for mod in init_order:
        try:
            print(f"  -> 初始化 {mod.name}...")
            mod.init()
            print(f"  {mod.name} 初始化成功")
        except Exception as e:
            print(f"  {mod.name} 初始化失败: {e} — 跳过")
            failed.append(mod)

    # 4. 发布系统就绪事件
    success = len(init_order) - len(failed)
    event_bus.publish(EVENT_SYSTEM_READY, {
        "total": len(init_order),
        "success": success,
        "failed": [m.name for m in failed],
    })

    if failed:
        print(f"\n系统就绪（{success}/{len(init_order)} 模块在线）")
        print(f"   离线: {', '.join(m.name for m in failed)}")
    else:
        print(f"\n系统就绪，{success} 个模块在线")

    # 5. 主循环
    print("进入主循环（事件驱动）")
    loop_count = 0
    try:
        while True:
            for mod in init_order:
                if not mod.ctx.get("is_init", False):
                    continue
                try:
                    mod.tick()
                except Exception as e:
                    print(f"[ERROR] {mod.name}.tick(): {e}")

            event_bus.pump()
            time.sleep_ms(10)

            # 每 2 秒打印一次数据快照
            loop_count += 1
            if loop_count % 200 == 0:
                print("\n--- 模块数据 (每 2 秒) ---")
                for mod in init_order:
                    if mod.ctx.get("is_init", False):
                        print(f"  [{mod.name}] {mod.get_data()}")

    except KeyboardInterrupt:
        print("\n系统已停止")


if __name__ == "__main__":
    main()
```

## 第三部分：核心业务链路验证（通经络）

### 3.1 守护主循环的"绝对纯净"（死守 tick < 5ms 红线）
在 MicroPython 中，主循环一旦被阻塞，整个系统就会"假死"。
*   **非阻塞陷阱**：`VoiceDriver` 的 `tick()` 必须先用 `uart.any()` 判断，绝不能写 `while uart.any(): data = uart.read()` 导致死循环。
*   **耗时陷阱**：`NavigationService` 的 TTS 播报必须确认丢到了后台线程；`CloudService` 的网络 I/O 必须在后台线程处理，主线程只做"数据入队"。
*   **EventBus 隔离**：`Event_Bus.py` 的 `pump()` 方法中，必须用 `try...except` 包裹**每一个**订阅者的回调，防止一个模块的 Bug 导致整个事件总线停摆。

### 3.2 EventBus 事件链条与 Payload 对齐
*   **常量对齐**：检查 `config.py` 中的事件名（如 `EVENT_VOICE_CMD`, `EVENT_RIDE_CONTROL`）是否被正确引用。
*   **BLEService v3 快照合并**：验证高频传感器事件进入环形缓冲区后，能否在 2000ms 的 tick 周期正确打包为 1 条 JSON（`t=0`）推送；控制状态变更（`EVENT_CONTROL_STATE_CHANGED`）能否正确合并为 `t=7` 推送，避免 notify 队列爆炸。
*   **防事件风暴**：确保没有 A 触发 B，B 又触发 A 的死循环。

### 3.3 多业务并发的优先级与仲裁
*   **音频通道抢占**：`AlarmService` 的报警音必须能**立即打断** `NavigationService` 的导航 TTS。
*   **报警态的"控制屏蔽"**：系统进入 `ALARM` 态时（`_alarm_active == True`），`ControlService` 应拦截并丢弃非紧急的语音/BLE控制指令，且 TTS 反馈必须静默。
*   **电源模式矩阵同频**：当 `ControlService` 发出 `EVENT_POWER_STATE_CHANGE` (如进入 SUSPENDED) 时，验证所有传感器是否降频，LCD/LED 是否关闭，`LightService` 是否暂停自动调光。

## 第五部分：集成测试与监控手段

### 5.1 破坏性测试用例（实车/实验室必做）
不要只测"正常操作"，请用"最坏的恶意"去揣测硬件和网络：
1.  **拔天线测试**：拔掉 GNSS 天线，看系统能否平滑降级（触发 `EVENT_GPS_LOST` TTS提示）并继续上传温湿度。
2.  **风噪误触测试**：在 `VoiceDriver` 旁边用吹风机吹噪音，看是否会误触发 SOS（验证速度条件校验）。
3.  **并发打断测试**：在播报长导航语音时敲击桌子触发碰撞，看报警音能否打断导航，且系统不死机。
4.  **BLE 脏数据轰炸**：用脚本向 BLE FFF3 疯狂发送超长/畸形 Hex 数据，看 `BLEService` 能否安然无恙，主循环是否卡顿。
5.  **断电重启测试**：在报警状态下直接拔掉电源重启，看系统初始化时 LCD 是否能正确恢复到 normal 模式（验证状态锁兜底）。

### 5.2 主循环性能与内存监控（保命代码）
在集成初期（尤其是 Step 2 和 Step 4），在 `main.py` 的主循环里加入以下监控代码。只要 WARNING 和 CRITICAL 不出现，集成就算成功：

```python
import gc
import time

# 在主循环 while True 内部：
loop_start = time.ticks_ms()

# 1. 执行所有模块 tick (需确保每个模块 tick 内部有 try-except)
for mod in modules:
    try:
        mod.tick()
    except Exception as e:
        print(f"Module {mod.name} tick error: {e}")

# 2. 事件泵 (EventBus 内部需隔离单个回调的异常)
event_bus.pump()

# 3. 性能监控 (死守 5ms 红线)
loop_cost = time.ticks_diff(time.ticks_ms(), loop_start)
if loop_cost > 5:
    print(f"WARNING: 主循环耗时 {loop_cost}ms，超过 5ms 红线！")

# 4. 内存监控 (每 100 次循环打印一次，防 MicroPython OOM)
if loop_count % 100 == 0:
    gc.collect()
    free_mem = gc.mem_free()
    if free_mem < 15000: # 根据 EC200U 实际剩余内存调整阈值
        print(f"CRITICAL: 剩余内存不足 {free_mem} bytes，疑似内存泄漏或事件风暴！")
```
